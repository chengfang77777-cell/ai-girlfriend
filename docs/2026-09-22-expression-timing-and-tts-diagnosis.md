# 表情时序回归与语音诊断

## 语音：已确认与尚未确认

用户要求先定位，再由用户选择语音处理方式。本轮诊断没有更改正式应用的合成超时、重试、音色或代理策略。

- 当前缓存的 7 个角色参考音频均为有效 WAV，约 9.6–12.8 秒，体积约 0.46–0.61 MB。
- 复制设置及角色数据到临时目录后，当前角色固定样本在 Flutter 测试中成功两次，约 4.8、5.7 秒。
- 用原目录 Windows Release 诊断入口调用当前系统代理、同一固定样本，成功两次，约 4.7、4.1 秒。诊断单次等待上限 90 秒、不自动重试；这只是诊断参数，不是正式应用配置。
- 早先 Windows Release 记录：一次约 5.9 秒成功，之后分别约 31.8 秒和 1.4 秒返回 HTTP 429。第一次 429 前发生了客户端重连。
- 正式应用当前单次合成上限 30 秒；超时或连接异常立即自动重发一次，HTTP 429 本身不自动重试。因此“语音生成超时”来自 HTTP 合成阶段，并非音频播放启动超时。
- 关闭客户端连接并不保证远端推理任务被取消。超时后立即重发可能重复提交尚在处理的合成，但当前证据不能证明历史 429 就是由这种重复提交造成。
- 本轮没有复现超过 30 秒的合成。不能把每一次超时都断言为服务器限流，也不能声称偶发超时已经修复。

官方文档说明：账号存在模型并发上限，负载高时可能延迟或返回 429；固定音色克隆目前没有真正的低延迟流式输出。

- https://mimo.mi.com/docs/zh-CN/api/guidance/rate-limit
- https://mimo.mi.com/docs/en-US/quick-start/usage-guide/audio/speech-synthesis-v2.5

给用户的待选方案：保留原固定音色，60 秒单次等待并对 429 有限退避；或 30 秒上限、失败手动重试；或本轮不调整策略。收到明确选择前保持正式语音代码不变。

## 表情根因

最近回复的元数据确实包含 happy、angry，并非所有回复都由模型输出 neutral。旧版本在文字到达时开始表情，约 4 秒完全消失；语音通常稍后才开始。此外 happy 在说话时只保留 25% 权重，实际最大约 0.05，难以辨认。

修复目标：文字先有短暂反应；对应音频真正开始时再次短暂表现同一情绪；长语音自动回到中立；启动及历史记录保持中立；新消息或换角色取消旧反应。以回复标识关联表情和音频，避免旧音频、重复播放或迟到事件恢复过期情绪。
