# 语音可靠性与全部心情表情

后续修正见 [2026-09-22 更新](2026-09-22-speech-proxy-and-brief-faces.md)：持续表情已改回短暂自然反应，并修复 Windows 系统代理适配。

## 问题与修复

- 原播放桥接不等待异步执行，播放器为空时直接返回，文件写入或浏览器播放错误仅记录日志。现由播放器回传带请求 ID 的开始、结束、失败事件，Flutter 等待结果并显示状态、错误和“重试语音”。
- 原先所有回复覆盖同一个 `audio.wav`，并通过定时轮询传递文件名。现每条语音使用独立文件、禁用缓存、直接派发播放命令，结束后清理文件；过期请求不能停止新请求。
- 启动播放器最多等待 10 秒；角色尚未就绪最多等待 15 秒；已开始的播放根据 WAV 实际采样参数加 15 秒余量检测卡住。合成请求 30 秒超时后给出明确提示。
- 原状态按 16 kHz 推算，而实际返回为 24 kHz。现在真实播放结束事件决定状态，WAV 时长仅用于超时兜底。
- 新角色首次使用的真实回复既播放也保存为固定参考，首次回复由两次串行请求减为一次。已有参考保持原样，后续仍克隆同一参考。播放失败重试复用已合成音频；合成失败重试重新请求，绝不偷偷换音色。
- 统一 `setEmotion` 与 `setExpression('_emotion', …)`，取消定时强制清空及身体动作结束清空表情。心情持续到下一次变化，权重平滑过渡并有轻微变化。
- 支持开心、害羞、生气、难过、惊讶、中立、拒绝、感谢。通道匹配忽略大小写，支持 VRM0 别名及 `Surprised` 自定义通道；没有害羞/脸红通道的模型用已有通道组合表达。
- 表情在身体动画之后更新，只控制情绪通道；眨眼、视线、口型分别保留控制。说话时降低组合表情强度，结束后平滑恢复。

## 验证

- Flutter 回归测试覆盖异步错误、无播放器、重试缓存、切换角色/停止、启动/播放超时、正确 WAV 时长、固定参考持久化和合成超时。
- Node 测试覆盖口型、Ctrl 滚轮路由、全部心情、表情被动画覆盖的回归、播放事件关联及旧请求清理。
- `tool/verify_viewer.py` 使用 Chromium 加载真实网页、7 个模型和 8 种心情，验证实际媒体播放开始/结束/失败事件，无 JavaScript 页面错误。结果和截图在 `build/verification`。
- `tool/tts_smoke_test.dart` 为手动启用的真实接口测试。仅复制设置到临时目录，不改动真实角色参考或聊天数据。2026-09-21 一次测试中设计约 4.76 秒、克隆约 4.69 秒，均返回有效 24 kHz WAV；这不是服务延迟保证。
- 使用 `D:\AIcursorclaude\flutter3245` 构建 Windows Release，输出仍为 `build\windows\x64\runner\Release\ai_girlfriend.exe`。

## 手动体验

启动原目录的新版应用，依次尝试普通对话、快速切换角色、连续发消息，以及触发各类心情。语音等待时应显示进度；网络或播放失败时应提示并提供重试。滚轮滚动消息，Ctrl+滚轮缩放模型。音色质量和完整音频生成速度仍受 TTS 服务影响，模型的表情细节受其原有形变通道限制。
